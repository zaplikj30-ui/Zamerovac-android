# #195 – diagnostika výkonu: nativní časování a lokální černá skříňka

**POUZE DIAGNOSTICKÝ DRAFT.** V této větvi je nově i uživatelské UI a lokální flight recorder; před fyzickým použitím je nutná nezávislá SOURCE/SECURITY kontrola a schválená samostatná testovací APK. Naměřená příčina zamrzání na Samsungu není známá. Bez schválení neinstalovat, nevydávat, nespouštět HOME ani cloud.

## Proč je potřeba minimální instrumentace

Android Studio Java/Kotlin Method Trace dokáže ukázat časy jednotlivých metod, ale může mít významnou režii a z prostých metod nedokáže přesně oddělit **čekání na monitor TrashPurger.LOCK** od práce pod ním. Chrome DevTools dokáže měřit WebView JavaScript bez modifikace app.js. V tomto PR jsou proto jen pevné časové značky android.os.Trace uvnitř původního Java saveDataChecked, pod compile-time bránou BuildConfig.DEBUG; nejsou v ostré release sestavě, nepřidávají bridge, oprávnění ani log s daty. Na Android 26+ je Trace.beginSection/endSection podporovaný. Neukládat jména, ID, obsah JSON, cesty, media bytes ani tokeny do trace.

Výchozí app/build.gradle má buildConfig true, debug signing a oddělenou variantu preview s applicationIdSuffix '.preview' a debuggable true. Jen tato oddělená preview verze po budoucím schválení, **nikoli instalovaný ostrý Zaměřovač**. U novější WebView 113+ je remote DevTools u debuggable app automatický, na konkrétním zařízení ověřit; pokud ne, poznačit NOT RUN a neodemykat ostrou aplikaci.

## Měřené časové úseky ve stejném Native vlákně

| Trace značka | Měří | Pozor |
|---|---|---|
| Z195-bridge | vstup do Java saveDataChecked až opuštění metody | jen Java bridge, ne celý JS/IME/paint |
| Z195-lock-wait | před synchronized(TrashPurger.LOCK) až získání LOCK | oddělené čekání na zámek |
| Z195-readDb | readDbForCas() | může skončit neúspěšným CAS ještě před zápisem |
| Z195-writeDb | writeDb(text) | dosavadní pevná hranice durable zápisu |
| Z195-generation | LocalDatabase.generation(...) | po write, před obnovou |
| Z195-recoverPrimary | PendingAudio(...).recoverPrimary().length() | po potvrzeném write; případná chyba nemění ACK |

Každá jednotlivá operace má výjimkově bezpečný try/finally pro Trace.endSection; vnější Z195-bridge také. Sekvence readDb → writeDb → generation → recoverPrimary a původní odpovědi CAS/exception nejsou změněné. Názvy jsou statické a bez metadat. Během trace spouštět jeden pokus najednou a vyhledat všech šest úseků; po chybovém CAS budou některé sekce správně chybět.

## Černá skříňka přímo v aplikaci – NOVÉ, fyzicky NOT RUN

Zobrazení: Nastavení → **Diagnostika výkonu (testovací)**. Tlačítka **Zapnout/Vypnout záznam**, **Historie a sdílení diagnostiky**, **Smazat všechna měření**. Implementace: `app/src/main/assets/flight-recorder.js`, načtený před `app.js`; zásahy do `editor.js` sledují otevření editoru, dokončený tah, dobu commit/save a následné kreslení. `app.js` sleduje čas Native bridge a status bez záznamu výsledného JSON, ID nebo obsahu chyby.

- **Opt-in**: výchozí stav vypnuto, oddělená předvolba v lokálním WebView `localStorage` (nikoli projekty/Native CAS). Omezení **120 událostí**; záznamy mají UTC čas a jen názvy z pevného seznamu + povolené numerické délky/počty. Zachovávají se po běžném restartu; při vymazání dat aplikace zmizí. Běžné diagnostické události se slučují po 1,2 s (samotné dotyky časovač nespouštějí); při dokončení tahu/varování a odchodu z obrazovky se vynucuje flush. Po tvrdém pádu může chybět poslední neuložený vzorek.
- **Časování dotyků editoru (návrh PR #231; fyzicky NOT RUN):** `input-down/up/cancel` jsou pouze události **doručené JavaScriptu** ve WebView, nikoli kompletní záznam fyzických dotyků Androidu. Číselná diagnostika obsahuje třídu vstupu (prst/pero/myš), zpoždění proti `event.timeStamp` jen při kompatibilních hodinách, počet souběžných pointerů a pohybových událostí a dobu **mezi JS callbacky**. Nezachycuje pozici, ID prstu, tlak, kótu ani hodnoty. U `input-down` počet zahrnuje nově stisknutý prst, u `input-up` už zvednutý prst nezahrnuje. Tyto události samy **nespouštějí 1,2s časovač ani diskový zápis**. Jestliže během drženého dotyku doběhne již dříve naplánovaný časovač nebo přijde jiná důležitá diagnostická událost, její automatický zápis se **odloží až za poslední `pointerup/cancel`**; více souběžných pointerů se počítá. Výslovné vypnutí měření, sdílení a `pagehide` dál používají původní okamžitý `flush()`. Když chybí koncová událost, poslední vzorky mohou zůstat v paměti až do explicitního flush nebo opuštění stránky. Po pádu aplikace mohou poslední neuložené dotyky chybět. Stávající Native/Perfetto časování a gestové ovladače se nemění. Jde o oddělený diagnostický krok, který **neopravuje** ukládání po 5 sekundách.
- **Měřené události**: start, otevření editoru, dokončený tah, velikost Undo a počet kót, celkový čas commit/save a kreslení, Native bridge, obecné selhání zápisu a prodleva webového UI (heartbeat 1 s, záznam při prodlevě větší než 1,6 s). Heartbeat není důkaz o konkrétních fyzických pixelech ani nativní ANR. Události neobsahují přesné délky, polohy, názvy zákazníků ani soubory.
- **Native debug/preview**: odpověď existujícího `saveDataChecked` obsahuje vedle původního ACK volitelné číselné `diag`: `lockWaitMs`, `readMs`, `writeMs`, `generationMs`, `recoveryMs`, `revisionCount` (počet při posledním čtení inventáře), `cacheHits`, `cacheMisses` (během daného save) a `mediaChecks`. Žádný nový `@JavascriptInterface`, žádné zákaznické údaje v odpovědi navíc; v release nejsou tyto diagnostické metriky přidávány.
- **Perfetto**: dosavadních šest `Z195-*` značek navíc doplněno o `Z195-revision-inventory` a `Z195-media-proof`. Jsou pouze v debug/preview, takže lze oddělit náklady revizní historie a ověřování médií od celého `writeDb`. Nezaměňovat tento systémový trace za zjednodušený in-app export.
- **Ruční export**: systémová nabídka Android `Native.shareText` posílá *až na kliknutí* anonymní textový report. Žádné automatické spojení, crash reporting do cloudu nebo upload na PUBLIC GitHub. Webový režim pouze zobrazí kopírovatelný text. Před sdílením má uživatel možnost report přečíst. Syrový Perfetto trace uchovávat lokálně.
- **Metodická výhrada**: zapnuté měření (zvlášť synchronní flush po dokončeném tahu) samo může přidat malé zdržení; porovnávat s vypnutou diagnostikou. Nevyhodnocovat stav na ostrých zakázkách. Tato funkce není lék ani automatická oprava.

**Praktické použití po schválené preview sestavě:** zapnout → otevřít syntetickou fotografii → opakovaně přesunout kótu a pustit → otestovat návrat z editoru/restart a druhou fotografii → v Nastavení sdílet report. Při nálezu `writeMs` s `cacheMisses` rozlišit podrobné časy `Z195-revision-inventory` a `Z195-media-proof` v Perfetto. Následuje měřená cílená oprava, vlastní i nezávislé review a fyzický retest; žádné oslabení CAS či integrity.

## Dočasný JS helper bez zásahu do produktu

Při budoucím povoleném testu v Chrome DevTools na odděleném testovacím WebView vložit obsah tools/diagnostics/issue195-folder-save-devtools.js do konzole. Není importován do app assets. Měří pouze vytvoření složky přes modal "Nová složka"; nečte názvy uložených zakázek ani JSON, jen boolean potvrzení a časové rozdíly.

Výstupní pole: clickToSaveStartMs (klik → JS save start); jsSaveMs (JS save včetně Native call a post-ACK); showFolderMs (synchronní UI DOM práce); clickToShowFolderStartMs (klik → začátek JS renderu); clickToTwoFramesMs (dva requestAnimationFrame, pouze orientační odezva, nikoli potvrzení fyzického pixelu); jsSaveReturnedTrue (pouze výsledná hodnota JS save). Tento boolean **není důkaz Native ACK**: starší save() může po potvrzeném zápisu vrátit false při následné UI výjimce. Skutečnou durable hranici určuje až úspěšné Native writeDb / potvrzení CAS. Při zavření zavolat v DevTools __z195FolderProbe.print() pro čistě číselný přehled, pak vždy __z195FolderProbe.stop() nebo reload WebView. Helper neodesílá síť, nezapisuje trvale, nepřepisuje výsledek původního save. Po odmítnutí prázdného názvu bez synchronního volání save() zneplatní čekající měření přímo na stejném tlačítku v ne-capture click listeneru **až po původním produkčním onclick** (který musí existovat před aktivací diagnostiky). Příští nesouvisející save se tedy nesmí přičíst složce; žádný microtask ani timer neurčuje čas zneplatnění. Ověř chybné jméno, zrušení/Cancel, dvojklik a následnou nezávislou akci. Po stop() nesmí žádný dříve naplánovaný requestAnimationFrame doplnit vzorek; stop() odstraní oba dočasné listenery a vrátí původní handlery.

**Neodečítej absolutní timestampy Android System Trace a JS performance.now od sebe**: není prokázán společný počátek. Srovnávat pouze délky odpovídajících operací a jejich časové pořadí; procenta počítat jen ze stejného prostředí a jedné testovací relace. Profiling sám přidává režii.

## Budoucí schválený fyzický test – připraveno, NOT RUN

1. Vlastník schválí konkrétní diagnostické SHA a použití izolované preview sestavy, podpis a balíček. **Bez schválení žádný build APK, instalace, HOME, Actions ani cloud**. Nikdy netestovat na skutečných zakázkách, nevydávat preview jako ostrou verzi.
2. Android Studio System Trace/Perfetto, pokud možno nízká režie. Na syntetických datech 3 zahřívací a alespoň 5 opakovaných Uložit kliknutí pro každý režim. Získat oddělené nativní úseky a JS časy z DevTools, po restartu readback potvrzených složek. Není-li WebView inspektovatelné, zapsat proč.
3. Matice: prázdná databáze, 50 a 500 syntetických dokumentů s přesnými kótami a původními *syntetickými* media IDs; žádná, pending a needs-review nahrávka; offline a sync zapnuto/vypnuto; selhání před potvrzením, retry, dvojklik, ukončení a znovuotevření. Žádné destruktivní plnění zákaznického disku ani původní média v logu.
4. Pro každý režim uvést n, median, maximum (případně p90), relevantní syntetickou velikost DB a především validaci ACK/RAM/durable JSON/mediálních ID/byte hashů na testovací instanci; zachovat jednotky, laserové hodnoty, historii, koš a pending journal. Rozlišit **durable write** od případně pomalé pozdější recovery a UI.
5. Pokud dojde k ztrátě média/ID, nepravdivému ACK, neúplné recovery, souběžné editaci bez správného CAS nebo k metodickému rozporu, **STOP**. Nepřebírat historický PASS 96/96 z PR #205 jako fyzické ověření.
6. Až s výsledky doporučit cílenou opravu měřeného úseku, jiné prostředí/profiler, nebo samostatný architektonický návrh s owner/design/security GO. Nevypínat PendingAudio.recoverPrimary, neoddalovat CAS ani nepřesouvat IO do pozadí naslepo.

**Současný stav:** SOURCE návrh, opt-in uživatelské UI a lokální recorder, statické Java kontrakty a simulovaný JS test; skutečná Android/Gradle kompilace, fyzické časy, média a restarty **NOT RUN**. Java trace metadata ani JS měřič nejsou bezpečnostní audit ani výkonový PASS. Offline nápověda byla aktualizována pro nové ovládání. Všechny skutečné trace soubory uchovat lokálně, před sdílením ručně prověřit i okolní systémové události a na veřejný GitHub zveřejnit jen anonymní souhrn čísel.
