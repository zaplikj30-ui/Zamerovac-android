# Číslování vydání Zaměřovače

**Schváleno 6. 11. 2026.** Od nové testovací APK **1.3.0** používáme významové číslování `HLAVNÍ.VEDLEJŠÍ.OPRAVA`.

- **Hlavní (2.0.0):** zásadní změna generace nebo nekompatibilní změna s plánovanou migrací.
- **Vedlejší (1.3.0):** významné nové kompatibilní funkce či větší ucelené aktualizace.
- **Opravné (1.3.1):** menší opravy a kompatibilní údržba.

**Historie:** 1.2.153 je poslední vydání starého číslování a obsahuje velkou aktualizaci #39. Vydání 1.3.0 zavedlo srozumitelnější verze; 1.4.0 již bylo skutečně vydáno jako `test-v1.4.0`. Starší tagy, historie i původní APK se nemění.

**Dvě odlišné hodnoty:** `versionName` je verze pro uživatele (například `1.4.1-test` v preview APK). `versionCode` je instalační celé číslo Androidu a musí být **vyšší než v poslední skutečně vydané, podepsané APK**. Gradle používá `1000 + GITHUB_RUN_NUMBER` jako technický výchozí mechanismus; schválený BUILD-only workflow přepočítá `GITHUB_RUN_NUMBER` **jen pro proces sestavení** podle ověřeného `versionCode` nejnovější vydané APK. Nedávat natvrdo číslo do Gradlu, nepoužívat jen nové počítadlo Actions. Nový `versionCode` a podpis se skutečně ověří přes `aapt`/`apksigner`, včetně package `cz.zamerovac.app.preview`. Historický `versionCode=1154` patří vydané 1.3.0; skutečný `versionCode` dnešní vydané 1.4.0 zde **není změřen** a nesmí se domýšlet.

**Skutečný stav k 18. 11. 2026:** GitHub Releases má poslední skutečnou APK **[test-v1.4.0](https://github.com/zaplikj30-ui/Zamerovac-android/releases/tag/test-v1.4.0)**. Ve zdrojové větvi pro další test je **kandidát `1.4.1`**, nikoli vydání, potvrzený build nebo fyzický PASS. Jeho jedinou doloženou změnou je technická údržba vydávacího procesu; netvrdí nové produktové funkce. Až po nezávislém review a schváleném merge do main může vlastník samostatně schválit BUILD. Vydání sestavené APK vyžaduje další samostatný RELEASE GO, instalace/fyzické ověření další krok. Příprava verzování žádný Actions run nespouští.

**Současný GitHub-native postup:** 1. read-only PILOT (jen se samostatným GO, žádné APK), 2. **BUILD-only** po ověření aktuálního main SHA a novější verze, 3. **RELEASE-only** na novém owner GO s konkrétním build run ID a SHA256 přesně stejných bajtů APK; nic znovu nekompiluje, nemění starý tag a ověřuje původ artefaktu/podpis/package/`versionCode`. Spouštěč je přes [issue #183](https://github.com/zaplikj30-ui/Zamerovac-android/issues/183) s přesnou owner syntaxí, případně schváleným manuálním `workflow_dispatch`. Nejsou povoleny automatické release po buildu ani historické `.github/apk-build-request.txt` nebo HOME workflow. Podrobnosti: [PR #186](https://github.com/zaplikj30-ui/Zamerovac-android/pull/186) a [issue #184](https://github.com/zaplikj30-ui/Zamerovac-android/issues/184).

**Zdroj marketingového čísla pro build:** `config/app-version.properties`. V aplikaci se zobrazuje skutečně **nainstalované** `versionName` z Android balíčku, nikoli číslo z webu nebo GitHubu. Historie `app/src/main/assets/release-history.js` je seřazena podle vydání a filtruje novější záznamy pro staré instalace. Před buildem musí `node tools/release/versioning.js --release` najít odpovídající první záznam, vyšší než předchozí položka; vůči skutečnému GitHub latest release kontroluje vyšší číslo samostatně `tools/release/apk_gate.py`. Obě kontroly zachovat a starší záznamy nepřeznačovat.

**Brány vydání:** nová APK pouze na výslovné vyžádání, CI úspěšné, správný podpis, balíček, zobrazená verze, `versionCode` větší než v nejnovější skutečně vydané APK, zákaz přepsání stejného tagu. Tag `test-vX.Y.Z`, soubor `Zamerovac-vX.Y.Z.apk`. Žádné mazání dat ani odinstalace stávající verze.

**Zbývá fyzicky ověřit:** instalaci budoucího vydání přes skutečně nainstalovanou 1.4.0 bez odinstalace/mazání dat, a dle potřeby starší upgrade cesty; originální fotografie, přesné editovatelné kóty, zálohy a synchronizaci na telefonu/tabletu. Automatické testy ≠ skutečné testy na zařízení.

## Changelog, offline nápověda a rozdíl mezi buildem a vydáním

Při **změně funkce, ovládání/chování, uživatelsky viditelného textu, názvu, ikony, menu, nastavení, importu/exportu, podpory zařízení, kompatibility či relevantního omezení** aktualizuj **v témže PR** českou offline nápovědu `app/src/main/assets/help.js` včetně postupů, chyb, odkazů a vyhledávacích výrazů. Ověř soulad UI a nápovědy v `tests/help_guide.js` a dle potřeby `tools/e2e/help.cjs`. Neplatí pro čistě technickou CI dokumentaci bez dopadu na uživatelské chování — tuto nerelevanci v PR vysvětli. V nápovědě dokumentuj jen skutečně fungující chování, ne budoucí nápad. **Dvě lupy jsou různé:** globální hledá zakázky/soubory/poznámky, lupa nápovědy jen kapitoly; offline nápověda nesmí číst ani odesílat zákaznické údaje ([#29](https://github.com/zaplikj30-ui/Zamerovac-android/issues/29), [PR30](https://github.com/zaplikj30-ui/Zamerovac-android/pull/30)).

**Offline changelog** `app/src/main/assets/release-history.js` má neměnné záznamy skutečně vydaných 1.4.0 a starších verzí a samostatný kandidátní záznam 1.4.1 s doloženou *technickou* údržbou vydání. Přítomnost kandidáta ve zdrojovém kódu **neznamená publikované GitHub Release, nový APK build ani otestovanou instalaci**. Po schváleném vydání není dovoleno ponechat falešný dočasný stav `prepared-not-published`; starší verze ani jejich obsah se nepřepisují. Testy `tests/release_history.js` a `tools/e2e/release-history.cjs` kontrolují dynamickou první verzi a neměnný historický suffix, aniž by hardcoded počet položek vytvářel falešný FAIL. Produktové novinky zapisovat jen na základě implementované změny, bez smyšlených funkcí. Build, vydání, skutečná instalace a fyzický PASS jsou rozdílné kroky. Spuštění vyžaduje konkrétní aktuální owner GO a kontrolu rozpočtu.

**Rozsah:** jen Zaměřovač, nikoli Konfigurátor–Nářezák; nedotýkat se schémat dat, zakázek, fyziky měření ani synchronizačních pravidel.
